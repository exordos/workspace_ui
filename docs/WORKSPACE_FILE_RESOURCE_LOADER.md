# Граница загрузчика файлов и локального кэша превью Workspace

Этот документ фиксирует границу ответственности между общим загрузчиком
ресурсов файлов и локальными кэшами визуальных потребителей.

## Общий загрузчик

Общий `workspace-file-loader` объединяет только незавершённые запросы по ключу:

```text
ownerKey + runtimeGeneration + fileUuid
```

Он не хранит готовый `Blob` или `ObjectURL`. Его задача — не запускать несколько
одинаковых сетевых запросов одновременно и передать результат ожидающим
потребителям.

Каждый визуальный потребитель создаёт собственные `AbortSignal` и ожидание.
Отмена или завершение одного ожидания не меняет ожидания остальных
потребителей.

## Кэш страницы чата

Страница чата сознательно держит локальный кэш `Blob`, привязанный к `ownerKey`.
Для каждого файла этот кэш создаёт одного долгоживущего потребителя общего
загрузчика и
удерживает его до смены conversation или runtime либо до размонтирования
страницы.

Поэтому отмена одного DOM-превью отменяет только его ожидание. Сетевой запрос
может продолжаться, потому что его результат нужен локальному кэшу страницы
чата. Это не нарушение границы общего загрузчика: сам загрузчик не превращается в
хранилище готовых ресурсов, а долгоживущий потребитель остаётся владельцем
кэширования.

Если в будущем потребуется отменять сеть сразу после исчезновения последнего
DOM-потребителя, это должен быть отдельный ref-counted cache/lease design.
Скрыто менять текущий загрузчик под такое поведение нельзя.

## Владельцы ObjectURL

У разных визуальных поверхностей разные владельцы `ObjectURL`:

- avatar владеет своими URL аватаров;
- message preview владеет URL превью сообщения;
- media viewer владеет URL своего просмотра.

Освобождение URL одной поверхностью не должно отзывать URL другой поверхности.

Настройки аватара теперь входят в Workspace avatar scope. Media viewer остаётся
отдельным этапом и не включается в эту границу автоматически.
