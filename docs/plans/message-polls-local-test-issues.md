## POLL-BUG-001 — Запрос стопки аватарок возвращал 400

Решение от 11 ноября 2026. Стопка показывает первые пять участников из стандартного списка API. Хронологическая сортировка отложена. На стенде 18082 обновлённая сборка прошла браузерный сценарий с 1, 2, 4, 5, 6 и 10 голосами, отзывом и повторным голосованием.

Кейсы POLL-041–044 и POLL-105. Подготовить открытый публичный опрос с 1, 2, 4, 5, 6 и 10 голосами и открыть его как Alice.

Frontend запрашивает `poll_voters?order=recent&page_limit=5`. Backend этой ревизии возвращает 400. Стопки пусты при правильных счётчиках голосов, поэтому порядок, обрезку успешной стопки и загрузку картинок на этой связке проверить нельзя.

Общий пункт «Посмотреть голоса» открывает список участников. Для него проверены пагинация 5+5, повтор после ошибки и сохранение первой страницы. У отдельных вариантов пустые кнопки стопки не видны и не фокусируются.

Доказательства — `bubble-results.json`, `pagination-ui2-raw.json`, исходный манифест стенда `/private/tmp/workspace-polls-mr317/avatar-fixtures.json`.

## POLL-BUG-002 — Принятое поведение архива и закрытой темы

Решение от 11 ноября 2026. Достаточно, что интерфейс скрывает композер и создание опроса. Приём запросов через API допустим.

Кейс POLL-092. На отдельном синтетическом чате установить `is_archived=true`; отдельно для темы установить `is_done=true`. Перед запросами подтвердить флаги через GET. Передавать точные `stream_uuid` и `topic_uuid`.

Создание опроса возвращает 201. Голосование, добавление варианта и сохранение настроек существующего опроса возвращают 200 в обоих состояниях. Прежняя матрица ожидала отказа API. В браузере кнопка создания скрыта и в архиве, и в закрытой теме.

Доказательства — `contracts-extra.json`, `backend-results.json`, `extra-results.json`.

## POLL-BUG-003 — После закрытия формы теряется клавиатурный фокус

Кейсы POLL-011 и POLL-101. Открыть создание опроса с клавиатуры, закрыть отменой, Escape либо кликом за пределами формы.

Форма закрывается, черновик сообщения сохраняется. Активным элементом становится `BODY`. Фокус к кнопке открытия не возвращается, клавиатурную навигацию приходится восстанавливать.

Доказательства — `forms-results.json`, `bubble-results.json` и снимки клавиатурного прогона.

## POLL-BUG-004 — При ширине 480 px карточка выходит за экран

Кейс POLL-035. Установить viewport 480×800 и открыть опрос.

Координаты карточки составили x=400..728, правая часть выходит за границу окна. Это наблюдение относится к общей компоновке чата с боковой панелью. Регрессия относительно основной ветки и минимальная поддерживаемая ширина отдельно не устанавливались.

Доказательства — `bubble-results.json` и снимок узкого экрана в каталоге артефактов.

## POLL-BUG-005 — Незавершённый выбор срока блокирует создание без объяснения

Кейс POLL-068. В форме создания включить срок и оставить дату невыбранной.

Создание становится недоступным, причина рядом с выбором срока не объясняется. Для прошлой даты и текущей минуты сообщение об ошибке появляется. Сервер отклоняет проверенные некорректные даты с 400.

Доказательства — `invalid-api.json`, `backend-results.json`, `deadline-extra.spec.ts`.

## POLL-BUG-006 — Переключение права добавления вариантов стирает введённый текст

Кейс POLL-065. Bob вводит новый вариант в опубликованном опросе. Автор выключает добавление вариантов, затем включает его снова.

Поле у Bob исчезает. При повторном включении оно пустое. Подтверждённый голос остаётся видимым. Повторный прогон 11 ноября подтвердил потерю текста без перезагрузки страницы Bob.

Доказательства — `toggle-without-reload-results.json`, `toggle-without-reload.cjs`.

## POLL-UX-001 — Вставка текста сверх лимита молча обрезается

Кейс POLL-010. Вставить в вопрос больше 1000 символов, в вариант больше 200.

HTML-поля принимают только первые 1000/200 символов. Граничные значения публикуются, прямые запросы на 1001/201 отклоняются сервером с 400. В UI пользователь не получает объяснения об обрезке вставленного текста. Матрица требует заметности потери текста, поэтому кейс отмечен ошибкой относительно этого ожидания.

Это UX-наблюдение для согласования поведения полей. Доказательства — `forms-results.json` и скрипты граничных значений.

## POLL-DIAG-001 — Запросы recent после смены ревизий требуют повторного замера

Кейс POLL-105. У опроса десять отвеченных вопросов. Установить задержку сети Chromium 500 мс, загрузить карточку и перейти в другой чат внутри приложения.

При смене снимков наблюдался краткий максимум девять запросов recent. Через десять секунд после перехода низкоуровневые события Chromium ещё показывали три незавершённых запроса. Контроль полной очистки не прошёл. Эти запросы обращаются к неподдержанному контракту из POLL-BUG-001. Причина наблюдения пока не установлена.

Успешную загрузку и отмену запросов следует повторно проверить на согласованной связке API и UI. Для вывода об утечке памяти требуются повторные циклы и профилирование.

Доказательства — `preview-request-timeline.json`, `performance.cjs`, `POLL-105-failed.png`.

## Уточнение матрицы — серверный переключатель создания удалён

Кейс POLL-015 проверен на временном API с `creation_enabled=false`. Backend всё равно создаёт опрос с 201. В проверяемом MR есть регрессионный тест, подтверждающий удаление этого переключателя.

Кейс помечен «Не применим» к текущей ревизии. Возврат переключателя потребует отдельного продуктового решения. Временные контейнеры проверки остановлены.
