## Повторная проверка POLL-086

Первый прогон отметил кейс как FAIL из-за требования отменять ожидание ответа на отправленный голос. В матрице уточнено, что отправленный голос может завершиться в фоне, а запросы списка и аватарок отменяются. Повторная проверка прошла в двух Chromium-контекстах на той же сборке. Код приложения для неё не менялся.

- Задержали живой REST-ответ на голос, заблокировали доставку одного `message.updated` голосующему и перешли в другую тему внутри SPA. До доставки HTTP 200 в IndexedDB был снимок ревизии 2 с одним голосом. После доставки появилась ревизия 3 с двумя голосами, выбранным ответом Alice и двумя UUID в превью. Старая карточка и модалка в новой теме не появились.
- Загрузили исходную тему заново с блокировкой входящих WS и REST-истории. Карточка показала выбор Alice, два голоса и аватарки до получения истории. После снятия задержки история вернула HTTP 200, выбор сохранился.
- Во втором сценарии задержали живой REST-ответ HTTP 200 с ревизией 4. Перед его доставкой более свежая ревизия 5 пришла по WebSocket. После доставки старого ответа в IndexedDB осталась ревизия 5, карточка сохранила актуальный выбор.
- В сценариях отмены четыре ответа API `poll_voters` с HTTP 200 были задержаны. Три запроса аватарок с `page_limit=5` без маркера и один запрос страницы с маркером M завершились в браузере с `net::ERR_ABORTED`.

Дополнительно прошли `npm run typecheck --workspace=web` и 185 целевых Vitest-тестов. `docs:check` и `git diff --check` прошли. Журнал Chromium содержит пути, число запросов, HTTP-статусы, отмены, `page_marker` и `page_limit`. Заголовки авторизации, токены и тела ответов в журнал не записывались.
