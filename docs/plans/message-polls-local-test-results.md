# Результаты расширенной локальной проверки опросов

Дата прогона — 10 ноября 2026.

Проверенная связка — backend MR #317 `c303d0a03a87b9d9ebf9369965214a7e4652ae0a`, frontend `64c3cb060b081af2c8fde418e05e939f25b487b8`, стенд `http://127.0.0.1:18082`. PostgreSQL 17, синтетический IAM, десять тестовых аккаунтов. В исходники приложения изменения не вносились.

Проверки выполняли основной агент и три субагента Terra. Использовались настоящий HTTP API, браузер Chromium и отдельная PostgreSQL для транзакционных тестов. Потери сети, ошибки ответов и задержки воспроизводились средствами Playwright и Chromium. Серверные provider-тесты используют имитацию Zulip.

По каждому из 106 кейсов назначен результат. Пройдено — **84**, ошибок — **8**, частично — **11**, заблокировано — **2**, не применимо — **1**. Для составных кейсов «Частично» означает, что оставшиеся условия перечислены в наблюдении. «Заблокирован» требует отсутствующей зависимости или исправления подтверждённого отказа. «Не применим» означает, что актуальный контракт не содержит проверяемой возможности.

[Матрица и ожидаемое поведение](message-polls-local-test-cases.md). [Отдельный список проблем](message-polls-local-test-issues.md).

## Замеры таймеров и памяти

В Chromium загрузили 100 опросов с будущим сроком и одну базовую карточку. Отрисована 101 карточка. Таймеров дедлайна было 100, после перехода внутри приложения в другой чат стало 0. Число отслеживаемых обработчиков focus/visibilitychange сократилось с 207 до 19 на новой поверхности.

Использованный JS heap после принудительной сборки мусора составил 11 033 816 байт до загрузки, 32 559 536 после загрузки и 24 228 016 после перехода. Эти значения включают карточки и кэш приложения. Порог приемлемого расхода памяти и длительность восстановления большой истории требуют отдельного согласования и замеров.

Данные — `timer-memory-measurements.json`, скрипт — `performance.cjs`. [Обсуждение общего таймера](../OPEN_QUESTIONS.md).

## Ограничения и оставшиеся проверки

Живой экземпляр Zulip и отдельная UI-сборка PR #423 к этому стенду не подключены. Provider-тесты подтверждают только своё тестовое окружение. У mock IAM один проект, поэтому отдельные переходы между организациями и проектами ограничены стендом.

Несовместимость `order=recent` мешает проверить успешное накопление изображений и часть сценариев отмены запросов на этой точной паре ревизий. HTTP-голоса, счётчики и общий список участников проверялись независимо.

У транзакционных проверок использовалась отдельная база. В одном прогоне на macOS для provider-тестов временно сопоставлялся TCP_KEEPIDLE с TCP_KEEPALIVE. Это адаптация тестового окружения. Исходники MR и рабочая база стенда сохранялись.
