## Расширенная матрица для следующего прогона

Каждая строка задаёт отдельную проверку с наблюдаемым результатом. При выполнении записываем статус, ревизии, аккаунт, способ проверки и ссылку на ошибку или артефакт. Фактические статусы расширенного прогона приведены в связанном отчёте. Предыдущие результаты в сводной таблице выше относятся к указанному объёму предыдущего прогона.

В текущем UI вопросы содержат варианты ответа. Проверяем одиночный и множественный выбор, каждый с правильными ответами и без них. Переключатель режима действует на весь опрос. Свободный текст, шкалы и разные режимы выбора у вопросов одного опроса потребуют отдельного продуктового решения.

### Подготовка данных и условий

- Автор Alice, участник Bob, администратор или модератор и пользователь вне чата. Для аватарок — десять разных голосующих.
- Опросы с 1, 2 и 20 вопросами. На вопрос — 2 и 20 вариантов, включая длинные строки, переносы, emoji и одинаковые подписи вариантов в разных вопросах.
- Обычный чат, архивный чат, закрытая тема, E2EE-чат, личный диалог, поверхности Activity и Feed, снимок пересылки.
- Открытый опрос без срока, с будущим сроком, истёкший и закрытый вручную. Результаты всегда видимы либо раскрываются после собственного ответа.
- Две независимые сессии браузера, русская и английская локали. Для сетевых кейсов раздельно управлять REST и WebSocket, задерживать ответы и сохранять журнал запросов без токенов.
- Серверные лимиты берём из проверяемой ревизии и конфигурации стенда. Текущие стандартные границы — 20 вопросов, 20 вариантов, 1000 символов вопроса и 200 символов варианта.

## Результаты и ограничения

Backend проверен в Linux на Python 3.12 и PostgreSQL 17. Прошли 72 unit-теста, 34 интеграционных теста и mypy для 102 файлов. В CI используется PostgreSQL 18. Его образ локально не удалось скачать из-за сетевой ошибки.

Frontend прошёл typecheck, 68 профильных тестов и два браузерных сценария с подменой API. В двух E2E-файлах обновлён ввод нового варианта через поле и Enter под текущий интерфейс. Проверки аватарок выполняются отдельным сценарием.

### Несовместимость последних аватарок

Воспроизведение — войти как Alice, открыть тему «Аватарки — граничные случаи», найти публичный опрос с десятью участниками. Счётчики отражают голоса, стопки аватарок пусты.

Текущий frontend запрашивает список с параметрами `order=recent&page_limit=5`. Опубликованный backend MR отклоняет `order=recent` с HTTP 400. Локальные изменения backend, использовавшиеся на стенде 18081, в эту ревизию MR не входят. Для совместимости требуется согласовать и опубликовать контракт последних голосовавших.

При пустой стопке кнопка входа в список голосовавших также недоступна для обычного клика. Получение списка без `order=recent` через HTTP работает. Браузерный тест аватарок завершается на первой проверке стопки, последующие шаги накопления, отзыва и повторного голосования в нём не выполняются.

### Границы проверки Zulip

В серверных интеграционных тестах provider заменён тестовой реализацией. Живая двусторонняя синхронизация с настоящим Zulip в этом прогоне не выполнялась. Локальная сборка frontend сохраняет ограничение native-only. Поддержка Zulip находится в отдельном [UI PR #423](https://github.com/exordos/workspace_ui/pull/423).

### Итог браузерного прогона

Первый полный прогон на подтверждённой связке дал 5 успешных сценариев и 2 ошибки — пустые аватарки и вход в список через пустую стопку. После выделения списка участников в отдельный кейс оставшаяся часть сценария публичного опроса прошла отдельным запуском. Все шесть основных сценариев проверены успешно. Проверки аватарок и входа в список через них остаются неуспешными.
