# Очистка Workspace при завершении сессии

[Общий план](../workspace-architecture-next.md#2-разорвать-зависимости-от-messenger) · [Жизненный цикл сессии](../workspace-runtime.md) · [Правила актуальности операций](../../../ORG_SCOPED_ASYNC_SAFETY.md#selected-screen-and-owner-operations)

Завершение авторизованной сессии отзывает право записи старого входа и очищает данные его владельца. `app` связывает auth с тремя владельцами: Messenger, users и внешними аккаунтами. [Завершение сессии](../../../../packages/web/src/entities/workspace-auth/workspace-auth.lib.ts) · [Сборка очистки](../../../../packages/web/src/app/workspace-session/workspace-session-cleanup.lib.ts)

## Граница ответственности

- **Workspace auth** решает, когда сессия завершается, синхронно удаляет её из store и передаёт обработчику `ownerKey` с проверкой актуальности удаления. Auth ждёт обработчик; ошибка обработчика не восстанавливает сессию.
- **Messenger, users и external-account** владеют очисткой своих данных. Messenger также останавливает свои операции и дожидается запланированных записей. Каждый владелец передаёт проверку актуальности в удаление своего кеша.
- **`app`** связывает auth с тремя владельцами через `installWorkspaceSessionCleanup()`. `main-app.tsx` устанавливает обработчик до монтирования React. Общая точка входа действует и для WebView. [Сборка очистки](../../../../packages/web/src/app/workspace-session/workspace-session-cleanup.lib.ts) · [Точка входа](../../../../packages/web/src/main-app.tsx) · [Выбор runtime](../../../../packages/web/src/app/app.tsx)

Сборка приложения регистрирует очистку владельцев через контракт auth.

```ts
type WorkspaceSessionCleanup = (ownerKey: string, isWriteCurrent: () => boolean) => Promise<void>;

registerWorkspaceSessionCleanup(async (ownerKey, isWriteCurrent) => {
  await Promise.allSettled([
    cleanupMessengerSession(ownerKey, isWriteCurrent),
    cleanupUsersSession(ownerKey, isWriteCurrent),
    cleanupExternalAccountSession(ownerKey, isWriteCurrent),
  ]);
});
```

`ownerKey` относится к данным одной сессии, независимо от выбранного аккаунта на экране. `isWriteCurrent` отвечает, можно ли ещё удалять данные для завершённого входа. Auth хранит одну регистрацию обработчика. Отписка для тестов или горячей перезагрузки действует только на свой экземпляр регистрации.

## Порядок очистки

1. Auth удаляет актуальную сессию из store синхронно. Явный выход, несовпадение владельца при refresh и завершение после повторяющейся ошибки refresh проходят через один путь. Вызов для отсутствующей или уже заменённой сессии завершается до очистки.
2. Подписка Messenger на auth store сразу отменяет утратившие актуальность операции, останавливает синхронизацию черновиков, освобождает криптосессии и очищает очередь исходящих. Она сохраняет `Promise` записей старого входа. При замене входа Messenger освобождает ресурсы через ту же подписку. Удаление долговременного кеша привязано к завершению сессии через auth.
3. Auth вызывает обработчик `app` после удаления сессии. `app` запускает очистку трёх владельцев параллельно и дожидается всех попыток через `Promise.allSettled`. Ошибка одного владельца не мешает остальным.
4. Messenger захватывает `Promise` записей черновиков до ожидания, затем удаляет кеш. Users и external-account удаляют свои записи по `ownerKey`. Все три операции используют переданную auth проверку актуальности; у users и external-account она действует и внутри IndexedDB транзакции. [Удаление кеша Messenger](../../../../packages/web/src/shared/lib/workspace-messenger-cache-db.ts#L692) · [Удаление кеша users](../../../../packages/web/src/shared/lib/workspace-user-cache-db.ts#L299) · [Удаление кеша внешних аккаунтов](../../../../packages/web/src/shared/lib/workspace-external-account-cache-db.ts)

Успешное обновление токена сохраняет идентичность входа. Переключение аккаунта меняет выбранный экран. Оба сценария продолжают работу владельца по действующим правилам. Холодный сброс по-прежнему синхронно отзывает управление записью у всех открытых сессий и запускает свой общий сброс хранилища. [Подготовка холодного сброса](../../../../packages/web/src/app/workspace-session/workspace-session-reset.lib.ts)

## Повторный вход во время очистки

Проверка для конкретного вызова очистки остаётся недействительной после первого появления нового входа с тем же `ownerKey`. Auth подписывается на изменение сессий до удаления старого входа, отслеживает появление нового экземпляра того же владельца и освобождает подписку после очистки. Если пользователь успевает выйти снова, пока первая очистка ещё ждёт запись, второй выход создаёт собственную проверку актуальности и ждёт свои записи перед удалением.

## Проверки сценариев

| Сценарий                                                                     | Ожидаемый результат                                                                                                                        |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Явный выход при задержанной записи черновика                                 | Сессия удалена сразу, удаление IndexedDB начнётся после завершения записи, а вызов выхода дождётся попытки удаления.                       |
| Отказ одной из очисток                                                       | Остальные владельцы всё равно запускают очистку; сессия остаётся завершённой.                                                              |
| Несовпадение пользователя или исчерпанные попытки refresh                    | Общий обработчик очищает ресурсы завершённого владельца. Другие аккаунты остаются активными, результат refresh сохраняет ожидаемую ошибку. |
| Быстрый повторный вход с тем же `ownerKey`                                   | Повторный вход отменяет право предыдущей очистки на удаление. Операции и кеш нового входа остаются доступны.                               |
| Выход, вход с тем же `ownerKey`, второй выход при задержанной записи первого | Первая очистка теряет право удаления навсегда. Кеш удаляет вторая очистка после завершения своих записей.                                  |
| Успешный refresh, переключение аккаунта, повторный вход поверх существующего | Refresh и переключение обходятся без долговременного удаления. Замена входа освобождает ресурсы старого экземпляра сессии.                 |
| Web, Electron и WebView                                                      | Обработчик установлен до запуска оболочки, независимо от наличия основного session runtime.                                                |
| Холодный сброс                                                               | Действующий вызов подготовки останавливает запись и транспорты, пока общий сброс очищает хранилище.                                        |
