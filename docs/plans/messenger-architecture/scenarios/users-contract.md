# Публичный контракт каталога пользователей

[Общий план](../workspace-architecture-next.md#3-открыть-контракт-users) · [Время жизни сессии](../workspace-runtime.md) · [Правила актуальности операций](../../../ORG_SCOPED_ASYNC_SAFETY.md#selected-screen-and-owner-operations)

Messenger, оболочка и runtime раньше обращались к `useUsersStore`, а функция обновления профиля и обработчик ссылки самостоятельно согласовывали каталог с кешем. Теперь каталог предоставляет публичные входы для чтения, операций профиля и синхронизации поверх существующих моделей сессий. Перенос в `modules/users` запланирован отдельным шагом. [Модель](../../../../packages/web/src/entities/user/user.model.ts) · [Чтение](../../../../packages/web/src/entities/user/users.ts) · [Профиль](../../../../packages/web/src/entities/user/users-profile.ts) · [Runtime](../../../../packages/web/src/entities/user/users-runtime.ts)

## 1. Чтение и подписки

- `useUserById` подписывается на одного пользователя, а `useUsersById`, `useUserIds`, `useUsersOwnerKey` и `useUserCount` возвращают отдельные поля каталога. Подписка строки на одного пользователя возвращает тот же объект при изменении соседа. Поиск, выбор участников, упоминания и список сообщений получают существующие ссылки на коллекции. Фильтрация и сортировка принадлежат потребителям.
- `readActiveUser` и `readActiveUsers` читают выбранную модель вне рендера. Вызывающий может задать ожидаемого владельца для чтения по UUID или сверить ключ снимка. При несовпадении владельца входящий звонок использует запасные подписи из чата и UUID.
- Сайдбар получает снимок каталога и подписку на его обновления. Переход на другого владельца по-прежнему публикует снимок сразу. Обычные изменения участвуют в существующем пакетировании, включая сброс при взаимодействии и возвращении на видимую вкладку. Для снимка с несовпадающим владельцем используется стабильная пустая карта. [Проекция сайдбара](../../../../packages/web/src/applications/messenger/features/sidebar/sidebar-projection.hook.ts)
- DevTools сохраняет `__dev__.stores.users.getState()` как чтение отдельной копии полей каталога для диагностики. [DevTools](../../../../packages/web/src/app/devtools.ts)

Сайдбар получает снимок через `readActiveUsers` и передаёт флаг смены владельца в существующий механизм публикации.

```tsx
const author = useUserById(message.authorUuid);
const usersById = useUsersById();
const userIds = useUserIds();
const unsubscribe = subscribeActiveUsers((ownerChanged) => changed(ownerChanged));
```

## 2. Запись после обновления профиля и ссылки

- После подтверждённого изменения профиля или аватара `applyOwnUserProjection(dto, runtimeContext, isCurrent)` проверяет UUID пользователя и актуальность выбранного владельца. Операция проверяет актуальность перед публикацией в модели и при записи в IndexedDB. Публикация в памяти предшествует попытке записи в кеш. Ошибка локальной записи сохраняет действующий режим best effort.
- Редактор профиля продолжает различать сохранение в IAM и обновление проекции. Если IAM уже сохранил изменения, временно устаревшие данные каталога приводят к `refreshPending`. Аватар сохраняет действующую классификацию ошибок и трактовку запоздавшего ответа. Действующий путь применения к модели без установленного владельца допускается только при уже актуальном запросе и остаётся внутри каталога. [API профиля](../../../../packages/web/src/features/user-profile/user-profile.api.ts)
- При переходе по ссылке `prepareSharedUserProfile(runtimeContext)` подготавливает модель выбранного владельца. Оболочка ищет профиль в памяти через `readActiveUser` или вызывает `restoreSharedUserProfile(runtimeContext, userUuid, isCurrent)` для восстановления из кеша. Затем `refreshSharedUserProfile(runtimeContext, userUuid, signal, isCurrent)` обновляет один профиль по HTTP и проверяет ожидаемый UUID. Кешированный профиль открывается до завершения HTTP и остаётся доступен при ошибке сети. Оболочка управляет панелью и поглощает хеш после однократного открытия. [Обработчик ссылки](../../../../packages/web/src/widgets/layout/layout-profile-share-link.ui.tsx)
- Перед публикацией ответа из ссылки каталог проверяет актуальность запроса UI, владельца, поколение сессии и сигнал отмены. После публикации проверка на границе IndexedDB использует владельца, поколение и сигнал. Завершение запроса UI после поглощения хеша не мешает записи уже применённого профиля.
- Уведомления используют `resolveCachedWorkspaceUser({ ownerKey, userUuid })` из `users-runtime.ts` для фонового поиска имени без обновления модели на экране. [Уведомления](../../../../packages/web/src/widgets/layout/layout-workspace-notifications.hook.ts)

## 3. Подключение runtime

`app` использует `reconcileUsersSessions`, `restoreWorkspaceSessionUsers`, `refreshWorkspaceSessionUsers` и `createUserRealtimeApplier` из `users-runtime.ts` и продолжает управлять порядком вызовов и транспортом. Каталог выполняет запросы и применяет результат к модели переданного владельца, включая фоновые события. `useHasUserForOwner(userUuid, ownerKey)` подписывает presence на готовность профиля без перезапуска при его редактировании. При истечении курсора runtime получает новый снимок каталога независимо от снимка Messenger. [Хост сессий](../../../../packages/web/src/app/workspace-session/workspace-session.hook.ts) · [Bootstrap](../../../../packages/web/src/app/workspace-session/workspace-session-bootstrap.lib.ts) · [Realtime](../../../../packages/web/src/entities/user/user-realtime-applier.lib.ts)

Внешние потребители получают каталог через публичные операции. Согласование модели с кешем выполняется внутри `entities/user`. Тестовые фикстуры могут подготавливать состояние модели напрямую.

## Проверки

| Сценарий                                                          | Ожидаемый результат                                                                                             |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Событие меняет пользователя B при подписке на A                   | Ссылка на пользователя A сохраняется. Сайдбар группирует обычные изменения, а смену владельца показывает сразу. |
| Переключение A → B → A                                            | Экран читает только выбранную модель и возвращается к данным A. Фоновая работа B сохраняет своего владельца.    |
| Открытие кешированного профиля по ссылке без сети                 | Панель открывается один раз. Фоновый запрос может завершиться после поглощения хеша.                            |
| Смена аккаунта, выход либо подмена UUID во время загрузки профиля | Запоздавший ответ не открывает панель и не записывает данные в чужой каталог или кеш.                           |
| IAM сохранил профиль, проекция ещё содержит старый снимок         | Действие возвращает успешный результат с `refreshPending`.                                                      |
| Bootstrap Messenger задержался или завершился ошибкой             | Каталог пользователей по-прежнему получает свой снимок. Realtime применяет события к владельцу транспорта.      |

Использовать существующие тесты `user.test.ts`, `sidebar-projection.hook.test.tsx`, `layout-profile-share-link.ui.test.tsx`, `user-profile.api.test.ts`, `workspace-session-bootstrap.lib.test.ts` и `workspace-session.lib.test.ts`. Проверить изменившиеся входы командой `npm run typecheck`, общие границы через `npm run arch:check`, ссылки через `npm run docs:check` и пробелы через `git diff --check`.
