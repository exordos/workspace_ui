# Realtime мессенджера

[Карта заметок](../README.md)

Начальная тема для разбора. Транспорт доставляет событие. Мессенджер направляет его владельцу данных и применяет изменение в контексте нужной сессии.

```ts
await messengerEvents.apply(session, event);
```

Текущий [хук realtime в оболочке](../../../../packages/web/src/widgets/layout/layout-workspace-realtime.hook.ts) подключает [обработчик событий мессенджера](../../../../packages/web/src/entities/messenger/messenger-realtime-applier.lib.ts). Обработчик уже участвует в подтверждении исходящих сообщений.

Для отдельного разбора:

- Кто получает курсор при [запуске](bootstrap.md), сохраняет его и определяет восстановление после разрыва.
- Как повторные события и запоздавшие HTTP-ответы влияют на [загруженную историю](load-messages.md#3-realtime-и-запоздавший-http).
- Где находится общий переход [подтверждения отправки](send-message.md#6-согласование-с-сервером), когда ответ и событие приходят в любом порядке.
- Как отделить работу активной сессии и фоновых аккаунтов, включая применение изменений в кеш.
