# Опросы в сообщениях

[Карта заметок](../README.md) · [Отправка](send-message.md) · [Сборка бабла](present-message.md)

Целевой сценарий рефакторинга. Опрос остаётся сообщением. `model/messages` владеет его подтверждённым состоянием и применяет команды, а `features/polls` связывает данные с формой, кнопками и обратной связью. В примерах имена файлов и сигнатуры условные.

## Состояние и границы

- `message.payload.kind === "poll"`. В `payload` лежат вопросы, варианты и параметры опроса. `pollState` в том же снимке сообщения содержит подтверждённые результаты, выбор текущего пользователя и ревизию.
- `model/messages/polls/` группирует типы и операции опроса внутри владельца `messages`. Команды загружают ответ и применяют его через правила модели сообщений. Фича читает подтверждённое состояние из публичного снимка сообщения.
- `features/polls` владеет формой создания, содержимым бабла, состоянием отправки действия и ошибками, диалогами и открытым списком голосовавших. Подтверждённые варианты, счётчики и выбранные голоса берёт из публичного снимка `messages`. Отображение результатов следует настройке видимости опроса.
- `features/timeline` владеет общей оболочкой бабла и вызывает `PollBody` через публичный вход фичи. Превью показывает краткое представление. Если используется тот же компонент в режиме просмотра, он скрывает действия.

Самостоятельный `model/polls` стоит рассмотреть, когда опросам понадобится собственное состояние или отдельный жизненный цикл. Подпапка внутри `messages` даёт правилам опроса свой адрес и сохраняет общий приём данных у владельца сообщения. ## От нажатия до запроса

`WorkspaceMessageBubble` по типу `poll` показывает `PollBody`. Фича проверяет доступность действия для UI, отображает ожидание и вызывает команду модели. Сервер проверяет участие, права управления, дедлайн и ограничения повторного голосования. Ожидание голоса относится к конкретному вопросу. Кнопки других вопросов могут иметь своё состояние.

```ts
// Внутри features/polls. Сигнатуры иллюстративные.
await messages.polls.setVote({ messageUuid, questionUuid, optionUuid, selected: true });
await messages.polls.setVote({ messageUuid, questionUuid, optionUuid, selected: false });
await messages.polls.addOption({ messageUuid, questionUuid, option: { uuid, text } });
```

`selected` задаёт состояние выбора, а повтор того же значения на сервере оставляет его прежним. Добавление варианта с его UUID само по себе не голосует. При неопределённом исходе повтор добавления использует тот же UUID и текст. Настройки и закрытие опроса можно публиковать как `messages.polls.updateSettings` и `messages.polls.close`. Для создания фича подготавливает `payload.kind = "poll"` и передаёт его в обычную отправку сообщения. ## HTTP и realtime сходятся в модели сообщений

Действия HTTP возвращают актуальное сообщение с персональным `pollState`. Realtime присылает изменение через `message.updated`. Оба входа передают данные владельцу `messages`, где снимок проверяется и применяются правила ревизии для пары `payload` и `pollState`. Остальные части сообщения, например реакции и прочтение, обновляются по своим правилам.

```text
Realtime приносит poll revision 42 → состояние опроса обновляется.
HTTP-ответ на более раннее действие приносит revision 41 → сохраняется версия 42.
```

При равной ревизии входящий снимок сохраняет факт закрытия, если опрос уже закрыт. Владелец проверяет UUID, принадлежность сессии и актуальность расположения сообщения перед применением ответа. Голос меняет состояние опроса, сохраняя прежний timestamp и unread сообщения. При ошибке или таймауте фича показывает ошибку только текущему владельцу, а последний подтверждённый снимок остаётся в модели. ## Шаг 5.4. Команды и подтверждённое состояние опроса

Фича опроса вызывает через `messages` голосование, добавление варианта, изменение настроек, закрытие и загрузку страницы голосовавших. Ожидание, ошибки, повтор с тем же UUID нового варианта, видимость и состояние открытого списка принадлежат фиче. Загрузка голосовавших возвращает страницу с прежним маркером и учитывает отмену. [Подключение опроса](../../../../packages/web/src/applications/messenger/features/polls/workspace-message-poll-connected.ui.tsx) · [Команды](../../../../packages/web/src/applications/messenger/model/messages/polls/messenger-poll-actions.lib.ts)

HTTP проверяет действующий контекст, UUID и размещение и передаёт принятый снимок в ту же внутреннюю операцию обновления `messages`, что и активный `message.updated`. HTTP-результат применяет подтверждённую пару `payload` и `pollState` с её собственной ревизией. Он сохраняет состояние прочтения, реакции и другие независимые поля текущего сообщения. Realtime применяет свои поля по действующим правилам. Равная ревизия сохраняет факт закрытия. Перемещение, удаление, отмена и смена поколения делают старую операцию неприменимой.

Кеш сохраняет подтверждённую пару и пригодные метаданные опроса. Для уже сохранённой строки обновление пары сохраняет прочтение и реакции кеша. Проверка перед завершением записи защищает удаление, новую версию опроса и смену владельца. Тесты сопоставляют HTTP и realtime в обоих порядках, закрытие при равной ревизии, актуальность размещения, независимые поля и состояние IndexedDB. [Правила store](../../../../packages/web/src/applications/messenger/model/messages/message.model.ts) · [Кеш сообщений](../../../../packages/web/src/shared/lib/workspace-messenger-cache-db.ts)

## Проверяемые переходы

| Ситуация                                             | Ожидаемое поведение                                                                    |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Добавили или убрали голос                            | UI обновляет выбор и результаты после применения актуального снимка `messages`.        |
| Ответ на действие пришёл после более нового realtime | Пара `payload` и `pollState` сохраняет более высокую ревизию.                          |
| Опрос закрыли, затем пришёл ответ с той же ревизией  | Опрос остаётся закрытым.                                                               |
| Добавили вариант ответа                              | Вариант и состояние вопроса приходят одним снимком. Само добавление не создаёт голос.  |
| HTTP-таймаут или смена сессии во время запроса       | Подтверждённые данные сохраняются. Ответ и ошибка старой сессии не меняют новый экран. |
