# От сообщения до бабла

[Карта заметок](../README.md) · [Полное дерево](../source-structure.md#дерево) · [Опросы](polls.md)

Целевая граница для рефакторинга. `model/messages` отдаёт сообщение окна. `features/timeline` собирает строку и выбирает содержимое общего бабла. Опрос имеет свой интерактивный компонент, а для E2EE выделяем общий хук подготовки расшифрованного текста. Имена файлов и сигнатуры в примерах условные.

## Кто отвечает за подготовку и рендер

| Случай                             | Откуда берутся данные                                                                     | Кто рисует содержимое                                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Markdown                           | `message.payload.content`                                                                 | Лента передаёт текст в `MarkdownBody` через существующий безопасный рендер.                                            |
| Опрос                              | Определение в `message.payload`, результаты и выбор пользователя в `message.pollState`    | `features/polls` предоставляет `PollBody`. Он показывает варианты и связывает кнопки с операциями владельца сообщения. |
| Служебное сообщение обмена ключами | `message.payload`                                                                         | Лента выбирает служебное представление.                                                                                |
| E2EE                               | `features/decrypted-message` получает зашифрованное сообщение и использует `model/crypto` | При успехе лента показывает тот же `MarkdownBody`. Для ожидания, отсутствия ключа и ошибки выбирает своё состояние.    |

`WorkspaceMessageBubble` находится в `features/timeline`. Он выбирает содержимое и сохраняет общие элементы сообщения: время, реакции, меню и выделение. Компонент опроса вставляется в эту оболочку и использует публичный вход `features/polls`. Цитата и сайдбар читают данные сообщения и самостоятельно выбирают компактное отображение. [Действующий выбор бабла](../../../../packages/web/src/applications/messenger/features/timeline/workspace-message-bubble.ui.tsx) · [Как опрос подключается к оболочке](../../../../packages/web/src/applications/messenger/features/polls/workspace-poll-message-bubble.ui.tsx)

## Выбор ветки по payload.kind

Тело определяется типом конкретного сообщения, включая `e2ee` внутри обычного чата. Markdown, опрос и служебные сообщения можно передать соответствующим компонентам напрямую. Единая обёртка готовности для них нужна только при конкретной пользе для вызывающего кода. [Текущая обработка содержимого](../../../../packages/web/src/applications/messenger/model/messages/messenger-message-content.lib.ts#L28)

```tsx
// features/timeline/ui/workspace-message-bubble.tsx
function renderBody(message: Message, decrypted: DecryptedBody | undefined) {
  switch (message.payload.kind) {
    case "markdown":
      return <MarkdownBody markdown={message.payload.content} />;
    case "poll":
      return <PollBody message={message} />;
    case "e2ee":
      return decrypted?.status === "ready" ? (
        <MarkdownBody markdown={decrypted.markdown} />
      ) : (
        <EncryptedMessageState result={decrypted} />
      );
    default:
      return <ServiceMessageBody payload={message.payload} />;
  }
}
```

Пример показывает выбор содержимого. Оболочка бабла, доступность действий и штатный рендер Markdown остаются в соответствующих компонентах. Секретные фрагменты внутри Markdown сохраняют собственный путь отображения. Подготовленный текст может сопровождаться признаком шифрования, если он нужен оформлению.

## Зачем отдельный модуль decrypted-message

`model/crypto` владеет ключами и криптосессиями и выполняет шифрование и расшифровку. Его операции нужны и фоновому `messages/outgoing`, и экрану. `model/messages` хранит серверный шифротекст. `features/decrypted-message` переводит результат криптографической операции в состояние, пригодное для показа, и следит, когда этот результат ещё действителен. Это узкая замена общей задачи `message-presentation` в целевом дереве.

```ts
type DecryptedBody =
  | { status: "ready"; markdown: string }
  | { status: "preparing" }
  | { status: "missing-key" }
  | { status: "error" };
```

Контракт принимает зашифрованное сообщение или набор таких сообщений и возвращает состояние, соответствующее текущему содержимому. Повтор подготовки и доступность запроса ключа можно передать через тот же контракт по потребности. Ожидание, отсутствие ключа и ошибка выглядят по-разному в ленте, цитате и превью. Общими у них остаются правила актуальности и повторной подготовки. `features/decrypted-message` предоставляет эти правила без визуального бабла. Интерфейс запроса ключа уже есть. Его можно выделить в самостоятельную фичу, если для управления ключами понадобится свой интерфейс и публичный контракт.

Сегодня эту работу выполняют `useMessagePresentations` и `useMessagePresentation`. Они используют `getImmediateMessengerMessageContent` и для незашифрованных типов. Целевой перенос оставляет асинхронную часть общей, а обычные данные могут идти напрямую в рендер. [Текущий хук](../../../../packages/web/src/applications/messenger/features/decrypted-message/message-presentation.hook.ts#L247)

## Передача данных от страницы к баблу

`MessengerPage` через `ConversationView` подключает `TimelineConnected`. `useTimeline` читает окно. Лента использует общий хук подготовки для зашифрованных сообщений окна и передаёт списку исходные сообщения, результаты расшифровки и обработчики. `WorkspaceMessageList` сохраняет прокрутку и собирает баблы. Сайдбар подписывается на последнее сообщение по UUID и использует тот же контракт подготовки в собственном превью. [Порядок рефакторинга списка](load-messages.md#порядок-рефакторинга-списка-сообщений) · [Текущее превью сайдбара](../../../../packages/web/src/applications/messenger/features/sidebar/sidebar-workspace-message-preview.ui.tsx#L11)

```tsx
// features/timeline/timeline-connected.tsx
function TimelineConnected({ conversationId }) {
  const timeline = useTimeline(conversationId);
  const decrypted = useDecryptedMessages(timeline.messages, conversationId);

  return (
    <WorkspaceMessageList
      messages={timeline.messages}
      decrypted={decrypted}
      onLoadOlder={timeline.loadOlder}
    />
  );
}
```

В примере хук отбирает сообщения `e2ee` из окна и предоставляет результат для текущей версии конкретного сообщения. Бабл и цитата переиспользуют уже подготовленный результат окна. Если своего подготовленного результата у поверхности нет, она может подключить подготовку одного сообщения, как это делает сайдбар. Сохраняем текущую оконную подготовку и повторное использование результатов при переносе. Правила показа ожидающих строк, переход на якорь и замена исходящей строки на серверную принадлежат ленте. [Текущая подготовка окна](../../../../packages/web/src/applications/messenger/features/timeline/workspace-message-list.ui.tsx#L736) · [Чтение готового результата и подготовка одного сообщения](../../../../packages/web/src/applications/messenger/features/decrypted-message/message-presentation.hook.ts#L273)

## Появление и отзыв ключа

UUID сообщения остаётся ключом строки. Попытка расшифровки привязана к владельцу, поколению сессии, потребителю, текущему шифротексту и доступу к ключу. Правка зашифрованного тела с тем же UUID делает результат старой попытки неприменимым. Обновление метаданных сохраняет идентичность содержимого.

При появлении ключа запускается подготовка для относящегося к нему содержимого. При отзыве ключа ранее показанный текст сразу заменяется состоянием `missing-key`. Перед публикацией запоздалого результата хук проверяет актуальность попытки. Та же защита действует при смене аккаунта, поколения сессии или потере доступа. [Текущая подписка на ключи](../../../../packages/web/src/applications/messenger/features/decrypted-message/message-presentation.hook.ts#L126) · [Проверка результата](../../../../packages/web/src/applications/messenger/features/decrypted-message/message-presentation.hook.ts#L183) · [Идентичность содержимого](../../../../packages/web/src/applications/messenger/model/messages/messenger-message-content.lib.ts#L23)

Открытый текст остаётся во временной памяти в границах владельца и доступа. Сейчас оконная подготовка может сохранить его в ограниченном RAM-кеше. При повторном чтении криптосессия сверяет ключ, а при смене контекста или отзыве очищает затронутые результаты. Каноническое сообщение и его долговечный кеш содержат серверный шифротекст. Границу между хуком и кешем уточняем при переносе, сохраняя инвалидацию и пакетную подготовку окна. [Публикация окна](../../../../packages/web/src/applications/messenger/features/decrypted-message/message-presentation.hook.ts#L230) · [Кеш подготовленных окон](../../../../packages/web/src/applications/messenger/model/crypto/chat-plaintext-window-cache.lib.ts) · [Инвалидация в криптосессии](../../../../packages/web/src/applications/messenger/model/crypto/chat-crypto-runtime.lib.ts#L1292)

## Проверяемые переходы

| Ситуация                                                              | Ожидаемое поведение                                                                           |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Ключ появился или отозван, пока сообщение видно                       | Бабл с прежним UUID меняет содержимое. Превью обновляется по тем же правилам доступа.         |
| Расшифровка завершилась после отзыва, редактирования или смены сессии | Запоздалый результат не публикуется.                                                          |
| Бабл и цитата показывают сообщение подготовленного окна               | Они используют готовый результат окна.                                                        |
| Изменение метаданных, догрузка или сокращение окна                    | Актуальные результаты переиспользуются, размер и состав RAM-кеша соответствуют текущему окну. |
| Изменилась высота бабла после расшифровки                             | Лента сохраняет позицию видимого якоря по правилам прокрутки.                                 |
