# Заметки об архитектуре мессенджера

Рабочие предложения для обсуждения. Действующие правила организации кода описаны в [архитектуре проекта](../../fsd-architecture.md).

| Тема                                            | Что здесь разбираем                                                                     | Связи                                                     |
| ----------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| [Границы модулей](modules.md)                   | Кто владеет состоянием, какие операции предоставляет, когда создаётся и останавливается | Все сценарии                                              |
| [Отправка сообщения](scenarios/send-message.md) | Черновик, очередь, оптимистичная строка, доставка, E2EE и отображение                   | Realtime и загрузка могут подтвердить отправку            |
| [Загрузка истории](scenarios/load-messages.md)  | Сценарий рефакторинга. Подписка ленты, границы окна и обработка запоздавших страниц     | Bootstrap даёт контекст, realtime меняет загруженное окно |
| [Bootstrap](scenarios/bootstrap.md)             | Запуск мессенджера, восстановление данных и смена сессии                                | Готовность данных, запуск realtime и фоновой доставки     |
| [Realtime](scenarios/realtime.md)               | События, восстановление после разрыва, порядок применения изменений                     | Сверка с HTTP, загрузкой истории и очередью               |

Как пополнять заметки:

1. Начни с этой карты и дополни страницу, которая владеет темой. Для нового сценария добавь страницу и ссылку сюда.
2. Покажи короткий вызов. Укажи, кто кого вызывает, где хранится состояние, кто вправе его менять и сколько оно живёт.
3. Свяжи пересекающиеся сценарии ссылками. Например, порядок подтверждения отправки описывается в отправке, а страница realtime ссылается на эту часть.
4. Отмечай, что уже есть в коде, что предложено и какие вопросы остались. Для текущего поведения оставляй ссылки на исходники, а для предложений — пример и ожидаемое поведение на спорных переходах.
