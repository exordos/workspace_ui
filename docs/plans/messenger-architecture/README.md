# Заметки об архитектуре мессенджера

Рабочие предложения для обсуждения. Действующие правила организации кода описаны в [архитектуре проекта](../../fsd-architecture.md).

Начни с [цели и принципов рефакторинга](principles.md). Они объясняют проблему координации и границу между бизнес-модулями, страницами и UI.

Для верхнего уровня выбрано разделение на `applications` (мессенджер, календарь, почта) и общие бизнес-`modules` (каталог пользователей). Дерево и направление зависимостей сохранены ниже. Точные контракты и внедрение ещё обсуждаются.

[Проектный навык Workspace module design](../../../.agents/skills/workspace-module-design/SKILL.md) помогает применять эти принципы при обсуждении архитектуры и согласованном рефакторинге.

Как пополнять заметки:

1. Начни с этой карты и дополни страницу, которая владеет темой. Для нового сценария добавь страницу и ссылку сюда.
2. Запиши, какую проблему решает модуль и что его граница упрощает. Покажи короткий вызов. Укажи, кто кого вызывает, где хранится состояние, кто вправе его менять и сколько оно живёт.
3. Свяжи пересекающиеся сценарии ссылками. Например, порядок подтверждения отправки описывается в отправке, а страница realtime ссылается на эту часть.
4. Отмечай, что уже есть в коде, что предложено и какие вопросы остались. Для текущего поведения оставляй ссылки на исходники, а для предложений — пример и ожидаемое поведение на спорных переходах.
