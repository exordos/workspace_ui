# Workspace user-flow map

This is a map of current UI entry points and known integration boundaries. A source link shows where a flow is wired, not a claim that it has passed production acceptance on every platform. Backend availability, permissions and deployment configuration must be checked against [PROJECT_FACTS.md](PROJECT_FACTS.md) and the linked contracts.

## Explicit integration limits

- Saved snippets and scheduled send are marked `unsupported` in the [Workspace composer capability wiring](../packages/web/src/pages/chat/chat-page-workspace.ui.tsx). The [saved snippets model](../packages/web/src/widgets/message-composer/message-composer-saved-snippets.model.ts) also reports unsupported rather than creating a fake successful item. These are frontend integration facts, not a universal claim about backend endpoints.
- [Composer section](../packages/web/src/pages/chat/chat-page-composer-section.ui.tsx) can receive a read-only reason and disables actions accordingly. Preserve the selected-conversation restriction instead of falling back to a legacy sender.
- The [realtime applier](../packages/web/src/entities/messenger/messenger-realtime-applier.lib.ts) records skipped/unsupported events. The presence of a connection is not proof that every possible event kind has a projection.
- Cache-first history, persisted drafts and an outbox do not by themselves establish complete offline operation, durable scheduled send or background delivery after the application exits.
- A route, settings panel, adapter or plugin hook is infrastructure evidence. End-to-end acceptance requires tracing it through the active data source and testing the requested flow. Plugin API permissions do not establish an execution sandbox; see [security boundaries](SECURITY_ARCHITECTURE.md).

## How to assess a requested change

Find the source entry point, verify the backend contract and runtime owner, then identify the observable behavior and its failure states. Report what was validated separately: source trace, focused tests, browser interaction, native-platform checks or a deployed integration. Do not restore a global checklist of completed features based only on source presence or legacy Zulip behavior.

Implementation guidance lives in [INTEGRATION_GUIDE.md](INTEGRATION_GUIDE.md). This map deliberately leaves product acceptance and deployment support to evidence from the specific task.
