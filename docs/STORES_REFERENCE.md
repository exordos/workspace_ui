## Loading and durable cache

[Bootstrap](../packages/web/src/entities/messenger/messenger-bootstrap.lib.ts) and [message loading](../packages/web/src/entities/messenger/messenger-messages-loader.lib.ts) coordinate data through the existing stores. [Adapters](../packages/web/src/entities/messenger/messenger-adapters.lib.ts) convert API DTOs into domain objects. Keep these responsibilities out of route components.

[Messenger cache helpers](../packages/web/src/entities/messenger/messenger-cache.lib.ts) sit above the [IndexedDB cache](../packages/web/src/shared/lib/workspace-messenger-cache-db.ts). Preserve cache-first rendering where the current loader supports it, then refresh server data and the applicable cache. A cache hit is not evidence that an operation is supported offline.

Async work captures the owner before it starts. `captureWorkspaceRuntimeRequestContext()` and `isWorkspaceRuntimeRequestInvalidated()` compare account, instance, organization, project, user and `runtimeGeneration`; an abort signal is an additional check. Guard both store writes and durable writes, including error/finally updates. Use the captured owner for cache keys rather than reading a newly active account after `await`. See [async safety](ORG_SCOPED_ASYNC_SAFETY.md).

Realtime applies through [messenger-realtime-applier.lib.ts](../packages/web/src/entities/messenger/messenger-realtime-applier.lib.ts) and [realtime cache handling](../packages/web/src/entities/messenger/messenger-realtime-cache.lib.ts). Cursor advancement, event ordering, active messages and background projections must stay consistent.

## Local UI state

Local state belongs near its owning UI. Examples include [settings](../packages/web/src/features/settings/settings.model.ts), [media viewer](../packages/web/src/features/media-viewer/media-viewer.model.ts), [theme](../packages/web/src/entities/theme/theme.model.ts) and [right drawer](../packages/web/src/widgets/right-panel/right-drawer.model.ts). Do not introduce a persistent entity store for a transient dialog unless its lifecycle requires one.

Use narrow Zustand selectors. Preserve stable derived values and references where consumers depend on them. Import from concrete files, and read the actual model for exported actions rather than copying an interface into documentation. Existing legacy or bridge modules are not templates for new Workspace state.
