## Loading and durable cache

[Bootstrap](../packages/web/src/applications/messenger/runtime/sync/messenger-bootstrap.lib.ts) and [message loading](../packages/web/src/applications/messenger/model/messages/history/messenger-messages-loader.lib.ts) coordinate data through the existing stores. [Catalog adapters](../packages/web/src/applications/messenger/model/chats/messenger-catalog-adapters.lib.ts) and the [message adapter](../packages/web/src/applications/messenger/model/messages/messenger-message-adapter.lib.ts) convert API DTOs into domain objects. Keep these responsibilities out of route components.

[Messenger cache helpers](../packages/web/src/applications/messenger/model/messenger-cache.lib.ts) sit above the [IndexedDB cache](../packages/web/src/shared/lib/workspace-messenger-cache-db.ts). Preserve cache-first rendering where the current loader supports it, then refresh server data and the applicable cache. A cache hit is not evidence that an operation is supported offline.

Async work captures the owner before it starts. `captureWorkspaceRuntimeRequestContext()` and `isWorkspaceRuntimeRequestInvalidated()` compare account, instance, organization, project, user and `runtimeGeneration`; an abort signal is an additional check. Guard both store writes and durable writes, including error/finally updates. Use the captured owner for cache keys rather than reading a newly active account after `await`. See [async safety](ORG_SCOPED_ASYNC_SAFETY.md).

Realtime uses the [Messenger owner applier](../packages/web/src/applications/messenger/runtime/sync/messenger-realtime-applier.lib.ts) and [cache operations](../packages/web/src/applications/messenger/model/messenger-cache.lib.ts). Each authorized owner keeps its own models and cursor. The selected screen subscribes to that owner's models.

## Local UI state

Local state belongs near its owning UI. Examples include [settings](../packages/web/src/features/settings/settings.model.ts), [media viewer](../packages/web/src/features/media-viewer/media-viewer.model.ts), [theme](../packages/web/src/entities/theme/theme.model.ts) and [right drawer](../packages/web/src/widgets/right-panel/right-drawer.model.ts). Do not introduce a persistent entity store for a transient dialog unless its lifecycle requires one.

Use narrow Zustand selectors. Preserve stable derived values and references where consumers depend on them. Follow the [module boundary policy](fsd-architecture.md#files-and-imports) for imports. Read the actual model for exported actions rather than copying an interface into documentation. Existing legacy or bridge modules are not templates for new Workspace state.
